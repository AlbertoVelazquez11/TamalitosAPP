## 3. Reglas de Negocio Consolidadas

- **Receta ↔ Producto:** 1:1. Solo productos **activos sin receta** se listan para crear receta.
- **Desactivar producto** → oculta su receta (no se borra). Reactivar → reaparece.
- **Eliminar receta** es una acción explícita e independiente.
- **Calculadora de producción:** dado `Q` a producir y receta base `R`, cada insumo = `cantidad_insumo × Q / R`, redondeado a **1 decimal hacia arriba**. Costo = `Σ (costoUnitario × cantidad)`; insumo sin costo = $0.
- **Producción:**
  - Si el producto tiene receta → precarga insumos proporcionales (editable).
  - Si falta stock → alerta informativa con cantidades faltantes; el usuario confirma y **se permite negativo**.
  - Guarda `costoTotal` (snapshot).
- **Perfiles (PDV):**
  - Siempre debe existir al menos 1 perfil para vender.
  - Perfil **"General"** creado automáticamente; ventas históricas se asignan a él.
  - Se puede editar; **no se elimina** si tiene ventas ni si es el activo.
  - Perfil activo se muestra dentro del botón "Registrar Venta".
- **Dashboard:** períodos unificados `día / 15 días / mes / 3 meses / anual`.

## 4. Modelo de Datos (delta v3) y Migración

| Store / Campo | Cambio |
|---|---|
| `recetas` (nuevo) | `id`, `productoId` (único), `nombreProducto`, `cantidadProducida`, `insumos[]` (`insumoId`, `nombreInsumo`, `cantidad`), `creadoEn`, `actualizadoEn` |
| `insumos` | + `costoUnitario` (number, default 0) |
| `producciones` | + `costoTotal` (number, snapshot) |
| `perfiles` (nuevo) | `id`, `nombre`, `creadoEn`, `actualizadoEn` |
| `ventas` | + `perfilId` (string), + `perfilNombre` (snapshot) |
| `config` (localStorage) | + `perfilActivoId` |

**Migración (DB_VERSION = 3):**
- Crear `recetas` y `perfiles`.
- Crear perfil **"General"**.
- Backfill: ventas existentes sin `perfilId` → asignar a "General".
- `config.perfilActivoId` se inicializa a "General" si no existe.

## 5. Interpretación de la Gráfica de Costos (Q10)

Se implementará como **gráfica de barras**: cada barra = una producción, **altura (Y) = cantidad producida**, y el **$costo** como etiqueta/valor visible de la barra (orden cronológico). Si en la revisión prefieres **X = $costo** literal, se ajusta sin rehacer la lógica de datos.
